Claude Code 把记忆当数据库建索引，然后拼命劝模型少写 ​

第一次看到 Claude Code 的记忆设计，我的反应是"这明明是个数据库"：常驻一个索引，细节散在数据页里，需要时才读。

但再往下看会发现，重点不在索引结构，而在写入端的减法。索引之所以能长期不溢出，不是因为压缩算法好，是因为官方明确规定了什么不能写。

一、两套系统，性质相反 ​

CLAUDE.md 和 auto memory 是两套东西：

  • CLAUDE.md 由人写，放指令。
  • auto memory 由 Claude 写，放它学到的东西。

两者每次会话都会加载，但都只是上下文，不是强制配置。

这个区别很重要：官方明确说 CLAUDE.md 作为 user message 放在 system prompt 之后，不保证模型严格遵从。想让规则变成硬约束，得用 hook 来拦截。

很多人以为写了 CLAUDE.md 就能约束住行为，实际上它更像一份"强烈建议"。

二、加载是拼接，不是覆盖 ​

CLAUDE.md 分四级作用域：

  1. managed policy
  2. 用户级 ~/.claude/CLAUDE.md
  3. 项目级 ./CLAUDE.md 或 ./.claude/CLAUDE.md
  4. 本地 ./CLAUDE.local.md

加载方式是从文件系统根逐级拼接到 cwd，不是覆盖。同一层里，CLAUDE.local.md 排在 CLAUDE.md 之后。

效果仍然是"越具体越优先"，但机制上是所有文件叠在一起，后出现的在上文里更靠后。

子目录的 CLAUDE.md 在启动时不加载，只有当 Claude 读、写、编辑该子目录的文件时才加载。这是为大仓库做的优化，避免一次性灌满上下文。

还有 @path 递归导入，最多 4 跳，代码块里的 @ 不算——这个细节说明他们考虑过误触发。

三、索引与数据分离 ​

auto memory 放在 ~/.claude/projects/<project>/memory/，按 git 仓库派生，同一个仓库的所有 worktree 共享。

记忆分四类，写在 frontmatter 的 type 里：user、feedback、project、reference。

体量控制是核心设计：

  • 启动时只读 MEMORY.md 的前 200 行或 25 KB，先到者为准。
  • 其余每条记忆拆成独立主题文件，模型需要时自己打开。
  • 接近上限时提醒压缩。
  • 超限写入仍然成功，但下次加载会被截断。

最后一条很关键：它不会阻止你写，只会让你写了看不到。这是一种"软失败"，比直接报错更隐蔽。

另外，写记忆文件时会在 frontmatter 记 modified（ISO 8601），供判断新旧。没有时间戳的记忆系统，迟早会被过期信息拖垮。

四、写入端的两条排除规则 ​

这是我认为最值得抄的部分。

官方明确排除两类内容：

  1. 能从代码库推导的内容。 grep 得到的、git 能查到的，不写。
  2. CLAUDE.md 里已经写过的内容。 不重复记录。

原因很直接：如果不去重，每次会话都在补重复信息，200 行的索引很快就会被塞满，然后开始截断，然后系统悄悄失效。

索引能长期工作的前提，是写入端足够克制。 大多数自建记忆系统失败，不是败在检索算法，是败在没有这两条排除规则。

五、子代理的隔离 ​

主会话的 auto memory 不会自动进入子代理。子代理可以用独立的 memory 目录。

这个设计暗示了一个判断：记忆是有作用域的，不是全局共享的。把所有记忆广播给所有子代理，等于让每个子代理都背上主会话的历史包袱。

六、这套设计的取舍 ​

优点很清晰：

  • 启动成本固定在一个小索引上，不会随记忆总量增长。
  • 细节按需读取，把固定成本换成按需成本。
  • 有明确的时间戳和截断机制，不会无限膨胀。
  • 写入端有减法，从源头上控制体量。

代价也很清晰：

  • 索引被截断是静默的，你不容易发现记忆已经失效。
  • 四类记忆（user/feedback/project/reference）的划分需要模型自己判断，判断错了就归错类。
  • 它是上下文不是约束，指望它强制改变行为会失望。

不确定性与边界 ​

  • 只采 Anthropic 官方 Claude Code 文档（memory、.claude 目录两页）。
  • 社区流传的"泄露源码分析"未采信为结论，只作为不确定性提示。
  • 四类记忆的具体划分标准、模型如何判断归类，官方文档未详细展开。
  • 本文以 2026-11-09 访问的官方文档为准。

总览见 三大编码 Agent 都没有记忆库，对照见 Codex 的记忆系统、Cursor 的记忆系统。
